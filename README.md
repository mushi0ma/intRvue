# intRvue

Android-приложение для текстовой подготовки к IT-собеседованиям (интерфейс на казахском и русском).
Курсовой проект КМ07: практические работы №1–8.

| Папка | Что внутри |
|---|---|
| `app/` | Flutter-приложение: feature-based структура, Material 3 по Figma, go_router, SQLite, kk/ru |
| `server/` | REST API и WebSocket на Dart (shelf) + PostgreSQL: синхронизация и ресурс тем ([endpoint-ы](server/README.md)) |

## Быстрый старт

```bash
docker compose up -d db                     # PostgreSQL 17 на 127.0.0.1:5433
(cd server && dart run bin/server.dart)     # API на 127.0.0.1:8787
cd app && flutter run                       # эмулятор Android
```

Демо-аккаунт: `aidana@example.com` / `intrvue2026`. Без сервера приложение полностью работает офлайн.

## Проверка

```bash
cd app && flutter analyze && flutter test   # 310 тестов (e2e синхронизации — при запущенном PostgreSQL)
cd server && dart test                      # 25 интеграционных тестов на PostgreSQL
```

## Release-сборка (№8)

```bash
cd app && flutter build apk --release       # build/app/outputs/flutter-apk/app-release.apk
adb install -r build/app/outputs/flutter-apk/app-release.apk
```

**Подпись.** Ключ берётся из `app/android/key.properties`. Файл в репозиторий не попадает.

```properties
storeFile=/абсолютный/путь/release.jks
storePassword=…
keyAlias=intrvue
keyPassword=…
```

Создать ключ:

```bash
keytool -genkeypair -v -keystore release.jks -alias intrvue -keyalg RSA -keysize 2048 -validity 10000
```

Если `key.properties` нет, release подписывается debug-ключом. Так проект собирается на любом компьютере, но публиковать такой APK нельзя.

**Сеть.** `res/xml/network_security_config.xml` разрешает release-сборке только HTTPS. Обычный HTTP открыт лишь для `10.0.2.2`, `localhost` и `127.0.0.1`: это компьютер с сервером, если смотреть из эмулятора, и само устройство. Debug-сборка (`src/debug`) пускает HTTP куда угодно, например на сервер в локальной сети:

```bash
flutter run --dart-define=INTRVUE_API=http://192.168.1.10:8787
```

Для настоящего сервера нужен HTTPS-адрес, тот же `--dart-define=INTRVUE_API=https://…`.

## Состояние и напоминания (№6)

**State management — Provider.** Репозитории (`AuthRepository`, `SessionRepository`, `TopicRepository`, `SettingsRepository`, `SyncRepository`) — это `ChangeNotifier`, которые раздаются через `MultiProvider` в `app/lib/app/app.dart`. Экраны подписываются через `context.watch`. Состояние приложения — это данные SQLite и настройки, а не сложные потоки событий, поэтому BLoC добавил бы шаблонный код без выгоды. Riverpod потребовал бы переписать уже покрытый тестами слой.

**Уведомления.** Используются `flutter_local_notifications`, `permission_handler` и `timezone`.
- Разрешение запрашивается в момент включения напоминаний. При отказе открывается экран с переходом в настройки Android; после возврата разрешение проверяется заново.
- Содержание напоминания строится из данных (`ReminderPlan`):
  - есть незавершённая сессия → предлагаем её продолжить;
  - иначе берём самую слабую тему последней полной сессии и открываем тренировку по ней;
  - если сессия уже была сегодня, сегодняшнее напоминание пропускается.
- `ReminderCoordinator` пересчитывает расписание при изменении сессий, настроек или аккаунта, а также при каждом запуске. При выходе из аккаунта все напоминания отменяются.

## Реальное время (№7)

**Сценарий.** Один аккаунт открыт на двух устройствах. Изменение на одном (новая тема, ответ, удалённая сессия) появляется на другом примерно через 0,2 с, и там показывается «Басқа құрылғыдан N өзгеріс келді».

**Как устроено.**
- Сервер (`GET /v1/live`, `shelf_web_socket`):
  - проверяет токен до upgrade;
  - принимает синхронизацию через сокет (`sync` → `synced`);
  - после каждого изменения (сокет, `/v1/sync`, REST `/v1/topics`) рассылает другим устройствам аккаунта `changed`.
- Своё устройство различается по заголовку `x-intrvue-device`.
- `changed` уходит только при реальном изменении снимка (sha256 без `server_time`), поэтому два устройства не пересылают друг другу бесконечные уведомления.
- Клиент (`LiveChannel`):
  - на `changed` забирает свежий снимок;
  - при обрыве переподключается с паузой 1, 2, 4 … 30 с;
  - после каждого подключения догоняет изменения, накопленные за время разрыва;
  - при разворачивании приложения подключается сразу.
- Если сокет недоступен, синхронизация идёт по HTTP, как раньше. Данные всегда остаются в SQLite.
- Код закрытия 4401 (токен отозван) отключает переподключение: приложение просит заново включить синхронизацию.

**Состояния на экране синхронизации.**
- «Қосулы» — соединение открыто.
- «Қосылуда…» — идёт подключение.
- «Байланыс үзілді… N с кейін» — связь прервалась; есть обратный отсчёт и кнопка «Қазір қосылу».

Обрыв — не ошибка, поэтому красного текста нет.

**Журнал.** `app/lib/core/log.dart`: в release выводятся только `warn` и `error`. Токены, пароли и email маскируются до записи.
